# Changelog (developer)

All technical changes to this project, written for whoever works on the code next.
`CHANGELOG.md` says what changed for the person installing the APK; this file says how it
was done. The method is the one `PiBOH/vivi-music-de` uses: **this file is the source** and
`CHANGELOG.md` is generated from it by `scripts/split_changelog.py`, never edited by hand.

The format is based on [Keep a Changelog](https://keepachangelog.com/en/1.1.0/),
and this project adheres to [Semantic Versioning](https://semver.org/spec/v2.0.0.html).

**How this file is used**

- Write the entry here once: a tagged, bold one-line head and the whole account indented
  under it. Then run `python scripts/split_changelog.py`; the short file keeps the head.
- Every bullet is tagged with the surface it changes: `- [APK] …`. Anisu has one surface,
  so every entry starts with `[APK]`.
- Categories are the Keep a Changelog ones, in order: `### Added`, `### Changed`,
  `### Deprecated`, `### Removed`, `### Fixed`, `### Security`. Omit the empty ones.
- `

## [Unreleased]

### Added
- [APK] **Live status while sources load and test.** The Extensions list now checks every installed source's website when it opens and shows, as each answers, whether it is online (with the time it took), down (for example "HTTP 530", which means the site's own server is unreachable), or can't be found at all (the domain doesn't exist or your DNS blocks it). Pressing Test now shows the step it is on as it happens: checking the site, loading the catalogue, listing episodes, asking for servers, resolving a stream. The buffering screen likewise lists what is going on in plain words under "Buffering…" (looking for sources, "AniLab: 2 servers found", "Reading the stream (HLS)…", a source that failed and the next one being tried), the newest line brightest. It follows the playback log, so what you see there is what the diagnostics report will say.
- [APK] **Subtitle translation.** The player's Subtitle settings panel has a new "Translate subtitles" box: switch it on, pick the language to translate into, and every subtitle line is translated before it is drawn. It uses Google's free web translation, so it needs an internet connection while it translates and adds nothing to the APK size (an on-device version was tried and added tens of megabytes). The language of the subtitle track in use is read from its name ("English", "Spanish"), falling back to English; the target starts as the phone's language. Translated lines are cached, so a line that shows again costs nothing, and a line that cannot be translated is shown as it was. **Constraint:** the subtitle text is sent to Google to be translated, picture-based subtitles (PGS/VobSub) cannot be translated, styling inside a translated line (italics, colours) is dropped, and subtitles sent to a TV while casting are the original files, not the translated text.
- [APK] **Blur when a poster opens and closes, and one switch for all the frosted glass.** Opening a details page from a poster now softens the page behind it while the poster grows, and sharpens it again as the page shrinks back, like a phone's home screen behind an app. A new Appearance > Glass > Frosted blur switch (on by default) controls every frosted effect: that blur, the blur behind the bars, menus and sheets, and a frosted sheen and light edge on glass cards and buttons. Off keeps the plain translucent glass everywhere. **Constraint:** the real blur needs Android 12 or newer (older phones keep the dimmed page), and cards and buttons that sit on the plain background get the frosted sheen rather than a see-through blur, because there is nothing behind them to blur.

### Changed
- [APK] **The nightly APK is always a nightly, whatever `version.txt` says.**
  `apk-nightly.yml`'s `plan` job no longer reads line 3: it hardcodes `CHANNEL=nightly`, names the build `${VERSION}-nightly`, and the matrix build step passes `-Pchannel=nightly` next to `-PversionName` / `-PversionCode`, so `BuildConfig.RELEASE_CHANNEL` is `nightly` on every nightly and the nightly-only rows in `AboutScreen.kt` (`onNightly`) and `UpdatesScreen.kt` show. Lines 1-2 are still read for the version and the code, and `release-apk.yml` still reads the channel. Verified locally with the workflow's exact property set (`RELEASE_CHANNEL="nightly"` over a file that says `stable`) and without it (`"stable"`).
- [APK] **Smaller APK.** The release APK now carries native libraries for phones only (arm64 and 32-bit ARM) and stores them compressed, drops unused resources, and keeps English strings only for the libraries it uses.
- [APK] **Casting now looks like the sketch.** Tapping the Cast button opens a "Casting" panel in the same style as Sources / Audio / Subtitles (a side panel in landscape, a bottom sheet in portrait) instead of the system dialog. It says "Searching…" with a Cast icon and magnifier while it looks, "No device found" with a crossed-out Cast icon when nothing answers after about 8 seconds, and lists every TV it finds as a card with a circle that fills in on the connected one; tapping a card connects. It closes by itself once a TV connects, and the Cast icon on the casting screen opens it again to switch TV. The casting screen is now black with the anime's banner colours flowing through it like water (six soft lights, one per region of the banner, each drifting on its own slow looping path and adding up where they cross) with a Cast badge, "Casting to <TV>", the title logo (plain title when it has none) and "Ep 12 : Episode name" (just "Ep 12" without a real name, nothing for a movie). Subtitles, the rewind / play / forward buttons and Stop casting moved into one bottom row under the seek bar to make room. **Constraint:** the flow is drawn without blur, so it looks the same on every Android version; with no readable banner the lights use the accent colour. On a phone without Google Play services the panel says Chromecast isn't available, replacing the old toast.

### Removed
- [APK] **Preload Last Episode is gone.**
  It buffered about a minute of the last-watched episode at launch, over the network and without being asked. Deleted `data/player/Prefetcher.kt`, its `AppContainer.prefetcher` wiring and the `container.prefetcher.prefetchOnLaunch()` call in `MainActivity.onCreate`; `PlayerPrefs.prefetchEnabled` / `setPrefetchEnabled` / `KEY_PREFETCH` (`prefetch_enabled`) and the `Preload` group in `ui/playersettings/PlayerStreamingScreen.kt`; the Settings subtitle no longer lists preload. `MediaCache` stays, because `PlayerViewModel` still plays through `mediaCache.dataSourceFactory()` / `upstreamWithHeaders()`. A saved `prefetch_enabled` value is simply never read again. The stale `fix/` snapshot tree that carried the old code is deleted with it.
- [APK] **The Halloween background animation is gone.** The pumpkins, bats and ghosts are removed from the background picker. If it was your background, the app now shows the plain one until you pick another.
- [APK] **Four settings are gone.** Ambient Mode, Pause Screen and Scale With Video no longer have switches: the glow under the video in the portrait player, the pause screen that dims the video and shows what you are watching, and subtitles that follow the size of the picture all simply stay on. Pause On Low Battery is removed completely, switch and behaviour: downloads no longer hold themselves when the battery is low, and only Pause all stops the queue. A saved value for any of them is ignored.

### Fixed
- [APK] **A nightly published a moment ago is offered at the next check.**
  `raw.githubusercontent.com` is served through a CDN that keeps a copy of `nightly.json` for about five minutes, so reopening the app and pressing check inside that window read the manifest from before the build and answered "up to date", which made a fresh nightly look undetected. `UpdateChecker.checkNightly` now appends a per-request `?refresh=<millis>` (a URL the CDN has not seen, so the request goes to the origin) and `get()` sends `Cache-Control: no-cache`. The commit comparison itself is unchanged, and the About / Updates rows are untouched.
- [APK] **The CloudStream pin is one JitPack actually publishes.**
  `gradle/libs.versions.toml` asked for `com.github.recloudstream.cloudstream:library:v4.5.4`, which never existed: JitPack's `maven-metadata.xml` lists `4.5.4` and `4.5.2`-`4.8.0`, but `4.5.4`, `v4.5.4`, `4.6.0` and `v4.6.0` all answer 404, so `:app:checkDebugAarMetadata` / `:app:checkReleaseAarMetadata` failed before a single line was compiled. The pin is now `4.5.3`, whose POM and `library-jvm-4.5.3.module` resolve. **Constraint:** the newer artifacts that do exist are not usable here: `v4.7.0` needs compileSdk 36, `v4.8.0` and `master-SNAPSHOT` need 37, and AGP 8.7.2 tops out at 35, so moving up means a toolchain bump, not a version bump.
- [APK] **`NiceHttp` is declared explicitly, because the library only leaks it at runtime.**
  CloudStream's `library-jvm` declares its real dependencies (`NiceHttp 0.4.13`, `jackson-module-kotlin 2.13.1`, `kotlinx-coroutines-core 1.10.1`, `fuzzywuzzy 1.4.0`, `rhino 1.8.0`, `NewPipeExtractor v0.24.6`, `tmdb-java 2.11.0`) as `implementation`, so they reach the runtime classpath but not the compile one. `CloudStreamRuntime.install` sets `app.baseClient` on nicehttp's `Requests`, and `compileDebugKotlin` failed with *Cannot access class 'com.lagradost.nicehttp.Requests'*. `libs.versions.toml` now has `niceHttp = "0.4.13"` plus `libs.nicehttp` (`com.github.Blatzar:NiceHttp`), declared in `app/build.gradle.kts` next to the CloudStream library.
- [APK] **The JDK instruction in `CLAUDE.md` §4.1 was wrong and is corrected.**
  Gradle does not read `org.gradle.java.home` from `local.properties` (only AGP reads that file, for `sdk.dir`). With the property sitting there, Gradle launched on the machine's JDK 25 and died inside the Kotlin DSL before configuring: `java.lang.IllegalArgumentException: 25.0.5` from `JavaVersion.parse`. The documented fix is now `JAVA_HOME` pointing at JDK 21, or `org.gradle.java.home` in a gitignored `gradle.properties`.
- [APK] **Navigation bar hides while scrolling and returns when you scroll back.** Dragging a list up slides the bar down out of view; dragging down brings it back, and it always returns when you change tab or leave a page. The bar's own code, look and blur are exactly as before: the heavier glass tint now applies only to content cards (a new `HeavyGlassCard`), not to the bar.
- [APK] **Smoother animations overall.** A baseline profile is added so Android compiles the app's screens, Compose and the image loader at install (the first open/close after an install or update no longer runs on the slower warm-up path), and the navigation bar's blur effect is set once instead of on every frame.
- [APK] **Cloudstream plugin errors name the missing piece.** A plugin that calls a CloudStream app class Anisu does not carry used to show a cut-off "NoClassDefFoundError: Failed r..."; the Test line now says "Missing class <name>" and may use up to five lines, so the exact class can be added.
- [APK] **Smoother details open and close.** The blur behind the opening poster was redrawn over the whole page on every frame (and the drifting background shapes redrew it again); it now moves in a few steps and reaches full strength halfway, so most frames reuse the finished blur, and the background shapes hold still while the page opens or closes. Strength is 18dp (was 22dp in the last build).
- [APK] **Glass cards, menus and sheets are as heavy as the navigation bar.** Cards and buttons were too see-through over posters and art; no glass card is now lighter than the navigation bar's weight, menus, sheets and dialogs have a firmer tint and a stronger blur behind them, and the small age-rating and season labels on posters are darker. **Constraint:** cards that sit inside a screen cannot blur the screen they are part of (only bars and pop-ups can), so they get the firmer tint rather than a see-through blur.
- [APK] **The Frosted blur switch is gone; the blur is always on.** Turning it off used to remove the blur from the navigation bar, the Extensions bar and card, menus, sheets and the long-press cards. Now none of it can be switched off: the poster open/close blur always runs (a little stronger, the same radius as the navigation bar's), and the heart and save buttons keep their frosted glass (haze and light edge) everywhere. The navigation bar still has its own Backdrop blur switch.
- [APK] **The pause screen now shows every time.** A paused stream keeps loading ahead and keeps flipping to "buffering", and that kept resetting the pause screen's timer, so on a slower connection it often never appeared. Buffering now only holds it back while playback is meant to be running. Its logo, season and episode details also no longer stay missing after one failed lookup of the show's artwork: the lookup is repeated a few times, a little later each time, until it answers. The episode's own description (synopsis) was missing whenever the page the player was opened from had no episode details, which happens when the details service times out and always when you open from Continue Watching; the player now looks it up itself and asks again a few times, and falls back to the show's description only when there really is none.
- [APK] **Chromecast search is sturdier and now tells you why it finds nothing.** The search asks the router for both plain discovery and an active scan, starts over every time the Casting panel opens, and re-reads the device list every two seconds instead of waiting for the router to announce changes. "No device found" now says why when it can (not on Wi-Fi, a VPN is on), shows a "Search again" button, and a small line with what the scan saw (routes seen / Cast routes / usable), so a report of a missing TV says where the search stopped. **Constraint:** if the line reads "0 routes seen", the phone's Cast service is not answering at all rather than the TV being missed.
- [APK] **The thin white line through the nav bar's selector pill is fixed for good when the bar is made rounded.** The earlier fix (one fill instead of three) did not touch the real cause: at high roundness the corner radius became exactly half the height, a perfect stadium with a zero-height straight band, and the GPU's rounded-rect drawing leaves a hairline seam through the middle of that shape. It only showed when Appearance > Nav bar roundness was turned up, which is why the default look never had it. The bar itself and the pill now stop a hair short of that shape (the bar at 49% instead of 50%, the pill 1dp under half its height), which looks the same but always keeps a straight band for the caps to meet on. The Extensions Available/Installed pill and the Schedule/News pill used the same radius and got the same fix. **Constraint:** at the default roundness nothing changes visually.
- [APK] **The Cast button now appears in the player.** Two things kept it hidden. The manifest lacked the two Wi-Fi permissions Chromecast discovery needs (`ACCESS_WIFI_STATE`, `CHANGE_WIFI_MULTICAST_STATE`), so the Cast framework could never see a TV. And the button only showed after a device had been found, but the framework only searches while its own route button is on screen, which the player never had, so nothing ever searched. The player now asks the media router for an active scan while it is open, and the button always shows; tapping it opens the device picker, which searches too. **Constraint:** the button now always shows while Settings > Player and streaming > Cast Button is on, even before a TV is found or without Google Play services; in that case the Casting panel says Chromecast isn't available instead of listing TVs.
- [APK] **The build works again.** Every debug and release build stopped before compiling anything, because the CloudStream library that lets Anisu load `.cs3` plugins was pinned to a version JitPack never managed to publish. It now uses the last version of that library line the repository really serves, and the small HTTP library the plugins make their requests through is included so the app compiles. **Constraint:** newer CloudStream releases need a newer Android SDK than this app builds against, so plugins stay on that version for now.
