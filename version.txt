# version.txt - the release metadata, read by app/build.gradle.kts and by the
# workflows. Three value lines, then these notes:
#   line 1 = version            line 2 = version code            line 3 = channel
# Lines starting with "#" are ignored everywhere (the readers strip them), so
# notes may be added here without renumbering the three value lines.
#
# line 1 - the SemVer base version. A release tag is "v" + this value and the
#          CHANGELOG.md heading for a release uses it without the "v".
# line 2 - the version code. It ONLY EVER INCREASES, and it must stay above
#          2026101113: the earlier workflows published date-based codes
#          (YYYYMMDDHH) up to that value, and Android refuses to install an APK
#          whose code is lower than the one already installed - the installer
#          reports exactly that as an "invalid package". 2026101200 is the
#          first code after all of them.
# line 3 - the channel, which is how the versioning is decided:
#            nightly  every build is named <version>-nightly-<YYYY.MM.DD.HHMM>
#                     and is published to the apk-nightly branch;
#            beta     <version> stays as it is, but the build is a pre-release;
#            stable    <version> stays as it is and the build is a release.
